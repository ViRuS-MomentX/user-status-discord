# Voice Bridge

Показывает в статусе Discord, в каком голосовом канале ты сидишь, на каком сервере
и сколько уже там находишься.

## Зачем вообще бот

Приложение, которое ставит тебе активность, не может спросить у Discord, где ты
сидишь: чтение голосового состояния закрыто скоупами `rpc` и `rpc.voice.read`,
которые Discord выдаёт по заявке. Зато это спокойно видит обычный бот, стоящий
на сервере.

Поэтому работа поделена надвое:

```
  Discord Gateway
        |
        v
  бот (Java, JDA)  --- http://127.0.0.1:7373/voice --->  CustomRP  ---> твоя активность
  видит, кто в войсе                  JSON                ставит статус
```

Бот только смотрит и отдаёт данные. Активность ставит CustomRP — потому что
присутствие пользователя может выставить лишь программа, запущенная рядом с
клиентом Discord.

## Что лежит в репозитории

| Папка      | Что это |
|------------|---------|
| `bot/`     | Java-бот на JDA. Следит за голосовыми каналами одного сервера. |
| `customrp/`| Патч к [CustomRP](https://github.com/maximmax42/Discord-CustomRP), который учит его забирать данные у бота. |

---

## Часть 1. Создать бота

1. Зайди на https://discord.com/developers/applications и нажми **New Application**.
2. В разделе **Bot** нажми **Reset Token** и скопируй токен. Показывать его никому нельзя:
   кто угодно с этим токеном управляет ботом.
3. Интенты трогать **не нужно**. Голосовые состояния (`GUILD_VOICE_STATES`) не входят
   в число привилегированных, галочки Presence / Server Members / Message Content
   оставь выключенными.
4. В разделе **OAuth2 → URL Generator** отметь скоуп **bot** и право
   **View Channels**. Больше боту ничего не требуется — он ничего не пишет и никого
   не двигает.
5. Открой получившуюся ссылку и добавь бота на свой сервер.

Понадобятся ещё два ID. Включи в Discord **Настройки → Расширенные → Режим разработчика**,
после этого правый клик по серверу даёт «Копировать ID сервера», а правый клик по себе —
«Копировать ID пользователя».

## Часть 2. Запустить бота

Нужна **Java 25 или новее**. Проверить — открыть PowerShell и выполнить:

```
java -version
```

Если команда не найдена или версия старее 25, поставь JDK с https://adoptium.net

Почему именно 25: Discord требует сквозного шифрования голоса, а библиотека,
которая его умеет, работает через нативный интерфейс Java, появившийся только в
этой версии. На Java постарее бот не запустится вовсе и скажет
`UnsupportedClassVersionError ... class file version 69.0`.

### Вариант А: взять готовый jar

Если `voice-bridge-bot.jar` уже собран, ничего клонировать и собирать не надо.
Положи `voice-bridge-bot.jar`, `run.bat` и `config.properties` в одну папку —
и переходи к настройке ниже.

### Вариант Б: собрать самому

Понадобится ещё и [Maven](https://maven.apache.org/download.cgi).

```
git clone https://github.com/ViRuS-MomentX/user-status-discord
cd user-status-discord\bot
mvn package
```

Готовый `target\voice-bridge-bot.jar` вместе с `run.bat` положи в любую папку.

### Настройка

Рядом с jar создай файл `config.properties` по образцу `config.properties.example`:

```properties
bot.token=токен-из-шага-2
guild.id=ID-сервера
user.id=твой-ID

http.host=127.0.0.1
http.port=7373
http.token=
```

Запускай двойным кликом по `run.bat` — он выставляет кодировку консоли, иначе
русские сообщения превратятся в кракозябры. Из PowerShell — так:

```
cd путь\к\папке\с\ботом
.\run.bat
```

Если всё верно, в консоли появится:

```
Подключился. Слежу за пользователем 573196687481372675 на сервере «Squad World».
Эндпоинт поднят: http://127.0.0.1:7373/voice
```

Проверить можно прямо в браузере, открыв http://127.0.0.1:7373/voice — должен
прийти JSON вида `{"connected":true,"inVoice":false}`.

Наружу эндпоинт не торчит: `127.0.0.1` означает, что достучаться до него можно
только с этого же компьютера. Поэтому `http.token` для локального запуска можно
оставить пустым.

## Часть 3. Собрать CustomRP с патчем

Патч сделан для коммита `935879f` репозитория `maximmax42/Discord-CustomRP`.

```
git clone https://github.com/maximmax42/Discord-CustomRP
cd Discord-CustomRP
git checkout 935879fb5ee87d60d4521489e1c811cc94e1f874
git apply ../customrp/customrp-voice-bridge.patch
```

Дальше открой `CustomRPC.sln` в Visual Studio и собери проект (нужен .NET Framework 4.8
и рабочая нагрузка «Разработка классических приложений .NET»).

Что патч добавляет:

* `VoiceBridge.cs` — опрашивает бота раз в 5 секунд;
* `VoiceBridgeForm.cs` — окно настроек;
* пункт **Настройки → Статус голосового канала** в меню;
* подстановку присутствия в `SetPresence()`.

Когда ты не в голосовом канале, приложение ведёт себя ровно как раньше.

## Часть 4. Настроить CustomRP

Открой **Настройки → Статус голосового канала** и включи галочку.

| Поле | Что делает |
|------|------------|
| Адрес бота | `http://127.0.0.1:7373/voice`, если порт не менял |
| Общий секрет | то же значение, что в `http.token`; пусто — если там пусто |
| Название активности | строка «Играет в …», по умолчанию `{server}` |
| Верхняя строка | шаблон для Details, по умолчанию `{server}` |
| Нижняя строка | шаблон для State, по умолчанию `{channel}` |
| Считать время | таймер с момента входа в канал |
| Ставить аватар сервера картинкой | вместо стандартного знака вопроса |

В шаблонах работают три подстановки: `{server}`, `{channel}` и `{members}` —
название сервера, название канала и сколько там живых людей. Например,
`{channel} — {members} чел.` даст `общий — 3 чел.`.

Кнопка **Проверить** сразу спрашивает бота по указанному адресу и пишет ответ
внизу окна, так что опечатку в адресе видно на месте. Если верхняя галочка при
этом снята, там же появится напоминание: проверка пройдёт, но на статус это
не повлияет.

Аватар сервера идёт через прокси `customrp.xyz` — так устроен сам CustomRP,
потому что Discord отказывается принимать ссылки со своего же CDN как внешнюю
картинку. Если у сервера иконки нет, картинка просто не меняется.

# Ранговая система

Второе, что умеет тот же бот: начислять монеты за время в голосовых каналах и
продавать за них роли.

## Как работает

Пока в голосовом канале сидит **минимум два живых человека**, каждому из них
капает время. За каждые 30 минут — одна монета. Сидящему в одиночестве не
капает ничего, в AFK-канале тоже.

Роли выстроены в лестницу. Повышение идёт строго по очереди: предыдущая роль
снимается, следующая выдаётся, цена списывается с баланса. До первого повышения
человек носит стартовую роль.

Роль с лестницы должна быть у **каждого**. При запуске бот проходит по всем
участникам и выдаёт недостающую: кто ничего не покупал — получает стартовую,
вернувшимся возвращается их купленный ранг. Новичкам роль выдаётся при входе.

Уже имеющиеся ступени бот не снимает. Ранг могли выдать вручную или он мог
остаться от прежней версии бота, и строгая сверка с балансами откатила бы людей
назад при первом же запуске. Поэтому только добавление.

Для обхода участников нужен интент **SERVER MEMBERS** — тот же, что и для роли
ботам.

Балансы лежат в `ranks.json` рядом с конфигом и переживают перезапуск.

## Команды

| Команда | Кто может | Что делает |
|---------|-----------|------------|
| `эмбед ранк` | управляющий сервером | публикует сообщение с лестницей и зелёной кнопкой «Повысить ранг» |
| `баланс` | любой | показывает монеты, текущий и следующий ранг |
| `ранг айди` | управляющий сервером | выводит ID всех ролей и коды эмодзи — для заполнения конфига |
| `очистить 20` | право «Управление сообщениями» | удаляет указанное число сообщений в канале |

## Что нужно включить

**Интент MESSAGE CONTENT.** Команды читаются из обычных сообщений, а это
привилегированный интент. На странице приложения: **Bot → Privileged Gateway
Intents → Message Content Intent**. Без него команды просто не будут
срабатывать. Пока `rank.enabled=false`, интент не нужен.

**Право «Управление ролями».** И, что важнее, **роль бота должна стоять в списке
ролей сервера выше всех выдаваемых ролей**. Discord не позволяет выдавать роли,
которые находятся выше твоей собственной, — это самая частая причина, по которой
кнопка не срабатывает.

## Настройка

Ступени задаются в `config.properties` по одной на строку, от дешёвой к дорогой:

```properties
rank.enabled=true
rank.coin=<:vcoin:123456789012345678>
rank.minutes=30
rank.start=<ID роли «Бездари»>
rank.1=<ID роли «Бич»>:3
rank.2=<ID роли «Вонючка»>:5
rank.3=<ID роли «Водолаз»>:10
rank.4=<ID роли «Минетчик»>:15
rank.5=<ID роли «Осёл»>:20
rank.6=<ID роли «Одарённый бездарствием»>:25
rank.7=<ID роли «Само бездарствие»>:30
```

Порядок такой: поставь `rank.enabled=true`, оставив ступени незаполненными,
запусти бота и напиши на сервере **`ранг айди`** — он выведет список всех ролей
с их ID и все эмодзи сервера в готовом виде. Остаётся скопировать нужное в
конфиг и перезапустить.

Пока ступени не заданы, бот об этом предупреждает, но команда `ранг айди`
работает — ради неё этот режим и существует.

Собрать то же самое вручную тоже можно: режим разработчика, правый клик по роли
→ «Копировать ID»; для эмодзи — написать `\:vcoin:` с обратной чертой и
отправить, в сообщении появится строка вида `<:vcoin:123…>`.

Вместо ID можно писать точное название роли, но у этих ролей в названиях длинные
тире — лишний повод для опечатки.

При запуске бот проверяет, что все указанные роли существуют, и пишет в консоль
те, которых не нашёл. Стоит заглянуть туда после первой настройки.

## Роль для ботов

`bots.role=<ID роли>` — и бот выдаст эту роль всем ботам сервера: при запуске
тем, кто уже есть, дальше новым в момент входа.

Понадобится интент **SERVER MEMBERS** (там же, где MESSAGE CONTENT): без него
список участников сервера не получить. И, как со ступенями, роль бота должна
стоять выше выдаваемой.

## Очистка канала

`moderation.enabled=true` включает команду `очистить 20`.

Ограничения тут не мои, а Discord: за раз удаляется не больше 100 сообщений, и
массовое удаление не работает со всем, что старше 14 дней. Такие сообщения бот
пропускает и пишет, сколько именно пропустил, — удалять их по одному значило бы
сотни запросов и минуты ожидания. Сама команда и отчёт об удалении убираются
следом, чтобы не оставлять мусор вместо мусора.

## Мост с Telegram

Связывает канал Discord и группу Telegram: написанное в одном появляется в
другом, с именем автора и вложениями.

```properties
bridge.enabled=true
bridge.channel=1531316074488795187
bridge.telegram.token=<токен от @BotFather>
bridge.telegram.chat=@defenseBrawl
```

Числовой ID группы знать не нужно: у публичной есть имя, и Telegram принимает
`@defenseBrawl` как есть. Для закрытой группы имени нет — туда пойдёт числовой
ID вида `-1001234567890`.

**Что нужно сделать в Telegram.** Завести бота у [@BotFather](https://t.me/BotFather)
командой `/newbot` и добавить его в группу. Дальше — важное: телеграм-боты по
умолчанию **не видят чужих сообщений** в группах. Чтобы мост работал в сторону
Discord, режим приватности надо снять:

1. `/setprivacy` у @BotFather → выбрать бота → **Disable**
2. Убрать бота из группы и добавить заново — иначе настройка не подхватится

Без этого половина моста из Telegram промолчит, а из Discord будет работать.

**Токен.** Держи его как пароль: у кого токен, тот пишет в группу от имени бота.
Если не хочется класть его в файл, задай переменную окружения
`VOICEBRIDGE_TELEGRAM_TOKEN` — она главнее файла.

**Как это выглядит.** В Discord сообщения из Telegram приходят под ником и
аватаркой написавшего — для этого нужна ссылка вебхука:

```properties
bridge.discord.webhook=https://discord.com/api/webhooks/...
bridge.avatars=true
```

Берётся она в настройках канала: Интеграции → Вебхуки → Создать → Копировать
ссылку. Без неё мост работает по-прежнему, просто пишет от имени бота одной
строкой.

К нику добавляется пометка `· Telegram`, и не для красоты: вебхук позволяет
назваться кем угодно, и без неё писавший в Telegram мог бы выдать себя за
участника сервера. Слова, которые Discord в именах вебхуков запрещает
(`discord`, `clyde`), заменяются — иначе сообщение просто не отправилось бы.

Аватарки спрашиваются у Telegram один раз за запуск и запоминаются: менять их
чаще, чем раз в полгода, никто не станет, а два лишних запроса на каждое
сообщение — заметно.

В Telegram уходит ник жирным с пометкой `· Discord`, а сказанное — моноширинным:
однострочное строкой, многострочное блоком. Моноширинный шрифт тут не украшение,
а способ сразу отличить пришедшее с той стороны от того, что пишут в самой
группе. Заодно чужая разметка не разъезжается по сообщению — всё, что человек
написал, экранируется.

**Вложения** переносятся целиком, в обе стороны: картинки Telegram показывает
прямо в ленте, остальное кладёт вложением. Предел — `bridge.maxmegabytes`, по
умолчанию 25 МБ; у самого Telegram потолок 50. Что больше — не переносится, но
о таком файле в группу уйдёт строка, чтобы пропажа не осталась незамеченной.

**Что мост не делает.** Он не пересылает сообщения ботов — ни своих, ни чужих.
Иначе две половины принялись бы возвращать друг другу одно и то же по кругу.
Упоминания из Telegram обезврежены: написавший там не сможет дёрнуть `@everyone`
на сервере, куда его не звали.

Пока бот не работал, переписка в группе копится, но при следующем запуске в
Discord не вываливается — мост начинает с того, что пришло после старта.

**Если Telegram не отвечает.** При запуске бот здоровается с Telegram и пишет
имя бота. Два разных исхода:

- `Telegram отказал: ...` — до Telegram дошли, и это он развернул. Обычно
  неверный токен. Мост выключается: ждать тут нечего, лечит человек.
- `Telegram сейчас не отвечает: ...` — связи нет. Мост всё равно поднимается и
  пробует снова: дорога может открыться к тому времени, как кто-то напишет.

Второе в России не редкость. Лечится двумя путями.

**VPN на всю систему** — ничего настраивать не надо, бот пойдёт вместе со всеми.

**Прокси только для Telegram** — остальное бот берёт обычным путём:

```properties
bridge.telegram.proxy=хост:порт
bridge.telegram.proxy=логин:пароль@хост:порт
```

Прокси должен быть **HTTP или HTTPS**. SOCKS не подойдёт: Java для этого его не
умеет. MTProto-прокси из телеграм-каналов тоже нет — их понимает сам мессенджер,
но не API для ботов, это разные вещи.

Токен прокси при этом не увидит: соединение с Telegram шифруется внутри тоннеля,
и снаружи виден только адрес `api.telegram.org`. Но выбирать прокси всё равно
стоит тот, которому доверяешь: он видит, что бот с Telegram разговаривает.

### Свой сервер Bot API

Когда `api.telegram.org` заблокирован наглухо — ни прокси, ни VPN не помогают —
остаётся путь, который обходит вопрос целиком. Официальная программа
[`telegram-bot-api`](https://github.com/tdlib/telegram-bot-api) работает на твоём
компьютере и говорит с Telegram по **MTProto**: тому же протоколу, что и обычное
приложение Telegram. Работает приложение — будет работать и она.

```properties
bridge.telegram.api=http://127.0.0.1:8081
```

Бот тогда стучится на `127.0.0.1`, а наружу ходит уже сервер — по протоколу,
который у тебя проходит.

Что понадобится: сама программа (для Windows официальных сборок нет, нужна
чужая или своя), а также `api_id` и `api_hash` с
[my.telegram.org](https://my.telegram.org) — сервер требует их при запуске.

Запускается примерно так:

```
telegram-bot-api.exe --api-id=ВАШ_ID --api-hash=ВАШ_HASH --http-port=8081
```

Две особенности, о которых бот знает сам:

- **Прокси при своём сервере не применяется.** Ходить через прокси на
  собственный компьютер незачем, а настроенный прокси это соединение сломал бы.
- **Аватарки из Telegram не подставляются.** За картинкой Discord ходит сам, а
  до твоего `127.0.0.1` он не дотянется. Ники в вебхуке остаются, аватарки —
  только у самого вебхука. Бот предупредит об этом в логе.

Если сервер откажется принимать бота со словами о другом сервере — значит токен
уже «прописан» на облачном. Разлогинить можно одним открытием ссылки
`https://api.telegram.org/bot<ТОКЕН>/logOut` откуда угодно, хоть с телефона по
мобильному интернету.

### Когда отвечает не Telegram

Когда по дороге отвечает не Telegram, а кто-то другой, бот говорит, кто именно:

| Что в логе | Что это значит |
|---|---|
| `прокси требует логин и пароль` | 407 — допиши `логин:пароль@` перед адресом |
| `прокси или провайдер не пустил запрос` | 403 — прокси не разрешает `api.telegram.org` |
| `прокси не дотянулся до Telegram` | 502/503/504 — у самого прокси нет туда дороги |
| `connect timed out` | до прокси вообще не достучались: не тот адрес или он не запущен |


## Лента постов сайта

`posts.enabled=true` — и бот объявляет в канале новые записи с сайта.

```properties
posts.enabled=true
posts.url=https://virus-momentx.vercel.app/posts.json
posts.channel=1531223486729552015
posts.minutes=10
```

Раз в `posts.minutes` бот читает ленту и сравнивает её с тем, что уже объявлял.
Новая запись выходит карточкой: сверху подпись «virus / интерактив» со значком
сайта, дальше заголовок со ссылкой на страницу постов, текст и картинка. Внизу
раздел решёткой — теми же словами, что на самой странице (`#личное`, `#игра`,
`#нейронки`), и время публикации.

Время отдаётся моментом, а не строкой: Discord показывает его в часовом поясе
читающего и сам подписывает «сегодня» или «вчера».

Полоса слева красится по разделу: зелёная у личного, лиловая у игр, синяя у
нейронок. У записей без раздела она серая.

Опрос выбран не от лени: сайт статический, сообщить о новой записи ему нечем.
Задержка до десяти минут — плата за то, что на стороне сайта ничего не нужно.

**Откуда берётся лента.** Посты живут в `posts-data.js` рядом с кодом страницы,
но этот модуль уходит в сборку под случайным именем — снаружи его не прочитать.
Поэтому сборка сайта выкладывает те же данные файлом `posts.json`. Он строится
из того же модуля, что и страница, так что разойтись с сайтом не может и правки
при добавлении поста не требует.

**Что бот считает новым.** Своего номера у постов нет, поэтому запись опознаётся
по дате, времени и заголовку. Список уже объявленного лежит в `posts-seen.txt`
рядом с настройками.

При первом запуске бот не вываливает в канал весь архив: он берёт ленту на учёт
молча и говорит только о том, что появится дальше. Если же за один заход нового
оказалось больше пяти, бот тоже промолчит — столько сразу означает, что ленту
пересобрали или поменяли заголовки, а не что написали пять постов.


## Музыка

`music.enabled=true` плюс ключ Last.fm включает четыре команды:

| Команда | Что делает |
|---------|------------|
| `start Кино` | включает популярные песни исполнителя |
| `start Группа крови` | включает эту песню, следом похожие |
| `скип` | следующий трек |
| `стоп` | остановить и выйти из канала |
| `очередь` | что играет и что дальше |
| `панель` | вызвать панель с кнопками вручную |

Зайди в голосовой канал перед `start` — бот подключится туда же.

## Своя фонотека

Скачанный трек играет всегда: ни таймаутов, ни блокировок, ни «площадка сегодня
отвечает через раз». Поэтому фонотека — основной источник, а поиск по сети
остался запасным.

```properties
music.library.enabled=true
music.library.folder=library
music.library.channel=1531223486729552016
music.library.ytdlp=yt-dlp.exe
```

**Как наполняется.** Заводишь канал и кидаешь туда ссылку на песню. Бот ставит
⏳, качает, меняет на ✅ и отвечает, что добавил. Не вышло — ❌ и строка с
причиной. Повторная ссылка на то же самое не качается второй раз: бот узнаёт её
и говорит, что трек уже есть.

**Что нужно поставить.** Качает не сам бот, а
[yt-dlp](https://github.com/yt-dlp/yt-dlp/releases) — своей качалки здесь быть
не может: площадки меняют защиту чаще, чем выходят сборки бота. Рядом с
`config.properties` кладутся `yt-dlp.exe` и `ffmpeg.exe` (звук вытаскивает он).
Там же ищется и файл с куками: имя без пути означает «рядом с настройками», как
и везде в боте, и только если файла там нет — его отдают системе искать по
своим путям. Обновлять `yt-dlp`
придётся самому, время от времени. Если его нет, бот скажет об этом при запуске
и просто выключит приём ссылок — играть из папки он всё равно будет.

**Что бот принимает.** Только площадки из `music.library.hosts`, всё остальное
отклоняется сразу: иначе в канал можно бросить ссылку куда угодно, и бот честно
потащит файл любого размера с незнакомого сервера. По умолчанию в списке есть и
те площадки, где музыку раздают законно — Bandcamp, Jamendo, Free Music Archive,
ccMixter, Internet Archive.

**Когда не качается.** Текст от yt-dlp бот показывает в канале как есть, но к
частым отказам добавляет совет:

| Что пишет | Что делать |
|---|---|
| `Video unavailable`, `not available in your country` | блокировка по стране — включить VPN и бросить ссылку заново |
| `Sign in to confirm`, `not a bot` | YouTube требует вход — нужны куки, см. ниже |
| `Could not copy ... cookie database` | до кук браузера не добраться — нужен файл с куками, см. ниже |
| `Unable to extract`, `nsig`, `format` | yt-dlp устарел — `yt-dlp.exe -U` |
| `Failed to establish a new connection`, `Socks`, `refused` | связи нет — убрать `--proxy` из `music.library.args` или поднять сам прокси |
| `The page needs to be reloaded` | YouTube не пустил клиента — `music.library.client=tv` |
| `Requested format is not available` | у этого клиента нет дорожки — попробовать другой клиент |

**Куки.** Часть роликов YouTube отдаёт только вошедшим. Взять куки можно двумя
способами, и они не равноценны:

```properties
music.library.cookiefile=cookies.txt   # надёжно
music.library.cookies=firefox          # проще, но работает не всегда
```

Чтение прямо из браузера ломается легко: тот держит свою базу кук открытой, а
Chrome начиная со 127-й версии на Windows ещё и шифрует её так, что снаружи не
разобрать — закрытие браузера тут не поможет. Firefox таким не страдает.

Файл с куками работает всегда. Выгружается расширением вроде «Get cookies.txt
LOCALLY», кладётся рядом с ботом. Если задан файл, браузер не смотрится вовсе.

**Клиент YouTube.** YouTube отвечает по-разному в зависимости от того, каким
приложением к нему пришли: то, что закрыто для браузера, нередко открыто для
телевизора или телефона. Переключается настройкой:

```properties
music.library.client=tv
```

Годятся `tv`, `android`, `ios`, `mweb`, `web_safari` — и несколько через запятую,
тогда качалка пробует их по порядку. Подбирать приходится руками: YouTube меняет
правила, и универсального ответа нет.

Настройка `music.library.args` передаёт качалке любые свои ключи через пробел.
Это способ починиться на месте, когда площадка сломалась, не дожидаясь новой
сборки бота. Оставь её пустой, если не знаешь, что туда писать: прокси там
прописывают, только когда он действительно поднят, иначе качалка будет
ломиться в него и падать при живом интернете.

Рамки на скачиваемое задаются настройками: не длиннее `music.library.minutes`,
не тяжелее `music.library.megabytes`, не дольше `music.library.waitminutes` на
одну закачку. Иначе однажды кто-нибудь зальёт восьмичасовой стрим дождя.

Качается только звуковая дорожка, а не ролик целиком, поэтому и мегабайты
считаются по ней: трёхминутная песня весит три-пять МБ. Звук берётся как есть,
без перегона в другой формат — у YouTube он и так в opus, а второй проход стоил
бы времени и качества.

**Как играет.** `start Группа крови` сначала ищет в фонотеке. Нашлось — играет
оттуда, и одна песня превращается в сеанс: следом идут другие треки того же
исполнителя, потом остальное вперемешку. Не нашлось — запрос уходит на площадку,
как раньше.

Файлы можно удалять руками. Бот сверяет опись с папкой при запуске и убирает из
неё записи, чьих файлов больше нет, — иначе такой трек однажды попался бы в
очереди и дал тишину.

**Про правовую сторону** — коротко и один раз. Скачивание с YouTube и
Яндекс.Музыки нарушает их правила, а хранение чужих записей — авторские права.
Для своих записей, Creative Commons и того, что артисты раздают сами, всё чисто.
Дальше решает владелец сервера.


## Панель

Панель появляется сама: после `start` она публикуется в текстовом чате того
голосового канала, куда подключился бот, и упоминает того, кто включил музыку.
Вручную её можно вызвать командой `панель` (или `плеер`) — тогда она выйдет
в том канале, где написана команда.

Новая панель заменяет предыдущую: старое сообщение удаляется, так что в чате
всегда висит ровно одна карточка, а не лента одинаковых.

В панели нет текста: только картинка-подсказка на зелёной полосе и три ряда по
пять кнопок. Что играет и что дальше, бот пишет обычными сообщениями в чат.

Полоса слева — это цвет карточки, другого способа её нарисовать нет. Ради неё
подсказка и лежит внутри карточки, а не отдельным вложением.

| | | | | |
|---|---|---|---|---|
| 🔉 тише | ⏮️ предыдущая | ⏸️ пауза | ⏭️ следующая | 🔊 громче |
| 🎄 новогодние | 🌸 весенние | 🔥 чарты | 🍂 осенние | ☀️ летние |
| 🔍 указать свою | 🎤 указать исполнителя | 🛑 остановить и выйти | 🔢 плейлист по коду | 🗑️ очистить очередь |

Кнопки без подписей, только иконки — различать их должна сама иконка, а не
цвет плитки. Подписи даёт картинка-подсказка внутри карточки: положи файл
с расшифровкой иконок рядом с `config.properties` под именем
`panel-legend.png`, и бот приложит его к панели сам — хостинг и ссылки не
нужны. Имя файла меняется настройкой `music.panel.legend`.

Если держать файл рядом неудобно, есть запасной путь: прямая ссылка на
изображение в `music.panel.image`. Она работает, только когда файла подсказки
нет. Проще всего загрузить картинку в любой канал Discord и скопировать
ссылку на файл.

### Свои иконки на кнопках

Картинку прямо в кнопку Discord не принимает — только эмодзи. Заводить их
руками не нужно: положи рядом с `config.properties` один лист 4×4 со всеми
шестнадцатью иконками, и бот при запуске сам нарежет его и создаст эмодзи
`vb_quieter`, `vb_previous` и остальные.

Иконки принадлежат приложению, а не серверу. Это важно: эмодзи сервера
расходуют его слоты, и шестнадцать штук съедают треть обычного запаса — панель
встала бы в очередь за картинками, которые нужны людям. У приложения запас
в две тысячи, он ничей, и прав на сервере для него не требуется.

Клетки читаются слева направо, сверху вниз:

| | | | |
|---|---|---|---|
| тише | предыдущая | пауза | продолжить |
| следующая | громче | зима | весна |
| чарты | осень | лето | своя песня |
| исполнитель | стоп | код | очистить |

Пауза и продолжение — две разные клетки: на кнопке они меняются местами, и
иконки нужны обе.

Требования к листу:

- PNG с прозрачным фоном. Если редактор запёк прозрачность шахматкой (в файле она
  лежит обычными пикселями, а не альфа-каналом), бот снимет её сам: заливает от краёв
  листа внутрь, так что фон уходит, а такой же цвет внутри иконки остаётся. По краям
  иконок может остаться тонкая кайма — на кнопке размером с ноготь её не видно.
  Если цвет иконок совпадает с фоном вплотную, бот это заметит и оставит лист как есть,
  предупредив в консоли.
- Иконки крупные и простые. В кнопке эмодзи показывается примерно 22×22 точки,
  тонкие линии там не читаются.
- Размер листа любой: бот обрезает пустые поля вокруг каждой иконки и приводит
  её к 128×128, так что клетки могут быть заполнены по-разному.

Никаких прав для этого боту не нужно, и свободные слоты на сервере не
требуются.

Если иконки заводила прежняя версия бота, они лежат в эмодзи сервера и занимают
его слоты. Новый бот убирает их сам и пишет об этом в консоль — но для удаления
ему нужно право **«Управление выражениями»** (Manage Expressions). Без него он
предупредит, и шестнадцать `vb_*` придётся удалить вручную в настройках
сервера.

Дальше лист не нужен: при следующих запусках бот находит готовые эмодзи по
именам и заново их не создаёт.

Чтобы поменять иконки, просто положи новый лист и перезапусти бота — старые
он удалит сам. Отпечаток загруженного листа бот хранит в файле
`panel-icons.state` рядом с настройками и сверяет его при каждом запуске: не
совпало — значит лист заменили, и старые `vb_*` уходят, а на их место встают
новые.

Имя листа задаётся настройкой `music.panel.sheet`, по умолчанию
`emoji-sheet.png`. Пока листа нет, на кнопках стандартные символы Unicode —
панель работает и без него.

Что стоит знать про отдельные кнопки:

- **⏸️ пауза** — одна кнопка на два действия, и иконка показывает, что она
  сделает: на паузе она превращается в ▶️.
- **⏮️ предыдущая** возвращает последний отыгравший трек, а прерванный ставит
  первым в очередь — он доиграет следом. Бот помнит полсотни последних треков.
- **🎄 🌸 🍂 ☀️** — обычный поиск по каталогу. Что именно искать, задаётся
  настройками `music.season.winter`, `.spring`, `.autumn`, `.summer`: запрос
  на русском и на английском находит разное, и какой нужен — решать владельцу
  сервера.
- **🔍 и 🎤** открывают окно ввода. Окно видит и заполняет только тот, кто нажал
  кнопку: у Discord окно ввода приходит в ответ на конкретное нажатие. Если
  кнопку нажали несколько человек, каждый получит своё окно, а в очередь
  просьбы встанут в порядке отправки — кто раньше написал, тот раньше играет.
- **🔢 плейлист по коду** пока отвечает, что функция не подключена: место под
  неё оставлено, сама она будет позже.
- **🗑️ очистить очередь** убирает всё, что ждёт, но текущий трек не трогает —
  чтобы оборвать и его, есть 🛑.

Панель правится на месте — новых сообщений в канал не сыплется. Кнопки
работают у всех, кто сидит в голосовом канале; если бот ещё не подключён, он
придёт в канал нажавшего.

Иконка паузы следит за плеером сама: когда трек кончается или музыку ставят на
паузу, кнопка перерисовывается. Правки копятся пару секунд и применяются
разом — иначе при загрузке плейлиста бот правил бы одно сообщение пятнадцать
раз подряд, а Discord за такое придерживает запросы.

**Плейлист подбирается, только когда ничего не играет.** Если музыка уже идёт,
`start` означает «поставь это следующим»: бот добавит ровно одну запрошенную
песню, и она заиграет сразу после текущей, не дожидаясь остатка очереди. Иначе
одна команда во время прослушивания хоронила бы очередь под чужим плейлистом из
пятнадцати треков.

Несколько просьб подряд выстраиваются в порядке поступления: просьба обгонит
подобранный плейлист, но не отберёт очередь у того, кто попросил раньше.

**Как определяется, что ты ввёл.** Сначала проверяется, не имя ли это
исполнителя: если каталог отдаёт артиста с ровно таким именем, играет его топ.
Иначе ввод считается названием песни — она ставится первой, дальше продолжение.
Сверка имени тут не для красоты: каталоги охотно «исправляют» запрос и на
«Группа крови» вернули бы песни Кино вместо самой песни.

**Звук берётся с SoundCloud.** Это надёжно и не требует ключей, но каталог
слабее: вместо студийных оригиналов нередко попадаются каверы и ремиксы.
Каталог подсказывает только названия, сам звук он не отдаёт.

**Каталог подсказок выбирается настройкой `music.catalog`:**

- `itunes` (по умолчанию) — без ключей, отвечает оттуда, откуда Last.fm
  отказывает. Выдача отсортирована по популярности, так что топ исполнителя
  получается сам собой. Но понятия «похожие песни» у iTunes нет вовсе:
  продолжением введённой песни идут другие популярные вещи того же исполнителя.
- `lastfm` — настоящие похожие песни, но нужен ключ с
  https://www.last.fm/api/account/create, и сервис отвечает не из любой страны.
  Отказ выглядит как `error 11, Access Denied` — это не про ключ, это про то,
  откуда пришёл запрос.

Если песня не нашлась на SoundCloud, бот берёт следующую из плейлиста, а не
отменяет весь запрос: в списке есть ещё полтора десятка, и одна пропажа не повод
оставлять канал в тишине.

Ожидание соединения с SoundCloud поднято с трёх секунд до пятнадцати. Штатные
три — это мало для длинного маршрута, и поиск отваливался там, где достаточно
было подождать.

Если каталог не отвечает, бот повторяет запрос трижды и только потом сдаётся,
написав «не отвечает, попробуй ещё раз». Это отдельное сообщение: «ничего не
знает про такое» означает, что сервис ответил и песни у него нет, а разовый
обрыв связи к этому отношения не имеет.

Первый трек запускается сразу, остальные догружаются фоном — каждый трек это
отдельный поиск на SoundCloud, и ждать полтора десятка значило бы слушать
тишину.

## Про шифрование голоса

Discord перевёл голосовые соединения на сквозное шифрование (DAVE). Своей
реализации у JDA нет — со встроенной заглушкой Discord закрывает соединение
через секунду, и бот бесконечно входит и выходит из канала. В логе это выглядит
как повторяющиеся пары «Бот вошёл» / «Бот вышел» и предупреждения
`Maximum Dave Protocol Version is 0`.

Лечится подключением `club.minnced:jdave-api` — реализации от сопровождающего
JDA. Она уже в сборке, ставить ничего не нужно.

Нативная библиотека шифрования в jar лежит **только под Windows x86-64**, как и
кодеки lavaplayer. Для переезда на Linux нужно убрать из `pom.xml` строку
`<exclude>natives/linux-x86-64/**</exclude>` и вернуть зависимость
`jdave-native-linux-x86-64`.

## Что стоит знать

**Время считается с момента, когда бот тебя увидел.** Discord не хранит, когда
человек зашёл в канал, — бот отмечает это сам. Если ты уже сидел в войсе, когда
бот запустился, отсчёт пойдёт с его запуска. Держи бота запущенным постоянно, и
время будет точным.

**Смена канала сбрасывает таймер**, а вот когда к тебе кто-то подсаживается —
не сбрасывает, обновляется только число людей.

**Бот и CustomRP должны работать на одном компьютере.** Так задумано: эндпоинт
слушает только localhost. Если захочешь унести бота на VPS, придётся открыть порт
наружу и обязательно заполнить `http.token` — иначе твоё местоположение сможет
прочитать кто угодно.

**Статус бота** задаётся строкой `bot.status`: `online`, `idle`,
`dnd` (не беспокоить) или `invisible`. По умолчанию «не беспокоить».

**Если бот выключен**, CustomRP через несколько секунд вернёт обычный статус,
настроенный в главном окне. Ошибок и окон с руганью не будет.

**Не запускай две копии бота с одним токеном.** Если где-то ещё работает старая
программа с тем же токеном, обе получат одни и те же события и будут отвечать на
команды дважды. Старую надо остановить.
